# Kambucha e-commerce 🫙

Витрина небольшой чайной фермы по производству комбучи — фронтенд на чистом JS (сборка через [Vite](https://vitejs.dev)) с реальной интеграцией оплаты через Stripe Checkout, задеплоено на [Vercel](https://vercel.com).

*[Read in English](README.md)*

Сетка товаров, выезжающая корзина и настоящий платёжный поток: нажатие на **Checkout** создаёт Stripe Checkout Session и перенаправляет на собственную защищённую страницу оплаты Stripe — номера карт никогда не попадают в этот код, что также избавляет вас от необходимости соответствовать PCI-DSS.

## Стек

- Vite 6 — сборка фронтенда
- Чистый JavaScript (ES-модули, без фреймворка)
- Serverless-функции Vercel (`api/`) — создают Stripe-сессии, проверяют вебхуки
- [Stripe Checkout](https://stripe.com/docs/payments/checkout) — защищённая страница оплаты + вебхуки

## Перед началом: получите ключи Stripe

Нужен собственный аккаунт Stripe — никакие платёжные данные не зашиты (и не должны быть зашиты) в этом коде.

Stripe выдаёт **два отдельных ключа** — всегда используйте подходящий под ситуацию:

| | Тестовый ключ (`sk_test_...`) | Боевой ключ (`sk_live_...`) |
|---|---|---|
| **Когда использовать** | Пока разрабатываете и тестируете | Только когда готовы принимать реальную оплату от реальных покупателей |
| **Где взять** | [dashboard.stripe.com/test/apikeys](https://dashboard.stripe.com/test/apikeys) — доступен сразу | [dashboard.stripe.com/apikeys](https://dashboard.stripe.com/apikeys) — сначала нужно [активировать аккаунт](https://dashboard.stripe.com/account/onboarding) (данные бизнеса, банковский счёт) |
| **Какие карты принимает** | Только [тестовые карты Stripe](https://stripe.com/docs/testing) (например, `4242 4242 4242 4242`) | Только настоящие карты |
| **Списывает ли деньги** | Нет — можно пользоваться сколько угодно бесплатно | Да — реальные списания, реальные выплаты на ваш счёт |
| **Вебхук** | Свой отдельный webhook endpoint (`whsec_...`) | **Другой**, отдельный webhook endpoint — тестовый и боевой вебхуки независимы, настраиваются раздельно |

Вебхук создаётся в Stripe Dashboard → Webhooks → Add destination → тип назначения **Webhook endpoint** (не Amazon EventBridge и не Azure Event Grid), URL — `https://ваш-проект.vercel.app/api/webhook`, событие `checkout.session.completed`; полученный signing secret добавляется в Vercel как `STRIPE_WEBHOOK_SECRET`.

**С чего начать:**

1. Заведите бесплатный аккаунт на [stripe.com](https://dashboard.stripe.com/register).
2. Возьмите **тестовый** секретный ключ в [API keys](https://dashboard.stripe.com/test/apikeys) (начинается с `sk_test_`).
3. Скопируйте `.env.example` в `.env` и вставьте ключ: STRIPE_SECRET_KEY=sk_test_...
4. Соберите и протестируйте весь путь оплаты на тестовом ключе — раздел [Переход на реальные деньги](#переход-на-реальные-деньги) ниже расскажет, как переключиться на `sk_live_...`, когда действительно будете готовы принимать настоящие деньги.

## Запуск

```bash
npm install -g vercel     # один раз, если ещё не установлен
pnpm install               # или npm install
vercel link                 # привязывает эту папку к проекту Vercel (создаст новый, если нужно)
cp .env.example .env
vercel dev                   # поднимает фронтенд И api/-функции вместе, на :3000
```

Именно `vercel dev` заставляет `/api/checkout` и остальное реально работать локально — обычный `vite dev` сам по себе serverless-функции не запускает.

```bash
pnpm build      # собирает фронтенд в dist/, чтобы проверить, что всё компилируется
```

## Как работает оплата

1. Человек нажимает **Checkout**. Браузер отправляет на `POST /api/checkout` только пары `{ id, qty }` по товарам в корзине — никогда не цену.
2. `api/checkout.js` сам ищет реальную цену для каждого `id` в `js/data.js` (тот же каталог, из которого рисуется витрина) и создаёт Stripe Checkout Session с проверенными на сервере позициями.
3. Браузер перенаправляется на защищённую страницу оплаты Stripe (`session.url`) для ввода данных карты.
4. Stripe возвращает обратно на `/success.html?session_id=...` или `/cancel.html`.
5. `/success.html` запрашивает `GET /api/session/:id`, чтобы найти сессию; только после подтверждения `payment_status: "paid"` от Stripe очищается локальная корзина и показывается подтверждение заказа.
6. Отдельно Stripe также вызывает `POST /api/webhook` напрямую сервер-сервер при завершении оплаты — это надёжный сигнал для фактического выполнения заказа (сам факт открытия `/success.html` не доказывает оплату, поскольку кто-то может открыть этот адрес, ничего не оплатив). Логику выполнения заказа (сохранение в базу, отправка чека, обновление остатков) нужно подключать в обработчик `checkout.session.completed` в `api/webhook.js`.

└── .env.example
## Деплой

```bash
vercel --prod
```

Или подключите GitHub-репозиторий напрямую в дашборде Vercel — деплой будет запускаться сам при каждом пуше в `main`, плюс превью-деплой на каждый PR. Отдельный CI-воркфлоу не нужен — за это отвечает встроенная интеграция Vercel с GitHub.

В любом случае переменные окружения задаются в **Vercel → Project → Settings → Environment Variables**:
- `STRIPE_SECRET_KEY`
- `STRIPE_WEBHOOK_SECRET` (см. выше)

Важно: у превью-деплоев каждый раз новый URL, поэтому вебхук, настроенный на продакшен-домен, не сработает для превью.

## Переход на реальные деньги

Когда будете готовы принимать настоящую оплату:

1. [Активируйте аккаунт Stripe](https://dashboard.stripe.com/account/onboarding) (данные бизнеса, банковский счёт) — обязательно перед тем, как заработают реальные списания.
2. Замените `sk_test_...` на **боевой** секретный ключ (`sk_live_...`) в переменных окружения Vercel и настройте отдельный live-вебхук в Stripe (тестовый и боевой — независимые друг от друга).
3. В зависимости от страны и того, что вы продаёте, могут быть обязательства по налогу с продаж/НДС, регистрации бизнеса и законам о защите прав потребителей при доставке еды/напитков — стоит свериться с бухгалтером или юристом в вашей юрисдикции перед запуском. [Stripe Tax](https://stripe.com/tax) может автоматизировать расчёт налогов, если пойдёте этим путём.

## О чём стоит знать

- **Корзина хранится только в localStorage** — привязана к браузеру, не синхронизируется между устройствами и не привязана к аккаунту.
- **Нет учёта остатков или базы заказов** — обработчик вебхука сейчас просто логирует событие; подключите базу данных (например, Vercel Postgres, Supabase), если нужны настоящие записи заказов.
- **Картинки товаров — заглушки** — замените файлы в `public/images/` на настоящие фотографии перед запуском.
- **Нет тестов** — `cart.js` состоит из чистых функций, с него проще всего начать.
